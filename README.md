# PC Builder — конфигуратор «сборка в 1 клик» и учёт мастерской

Система для мастерской по сборке ПК: **сборка ПК в один клик** по бюджету и сценарию
(офис, игры, монтаж видео, 3D-моделирование, стрим, универсальный), каталог комплектующих
с полными характеристиками, два интерфейса (**клиент** и **сборщик**), заказы, оплата,
приёмка комплектующих, складской учёт, логистика с трекингом и подтверждением получения.

**Всё в одной папке. Внешних зависимостей нет — `npm install` не нужен.**
Нужны только Node.js 22.5+ и встроенная SQLite (`node:sqlite`).

## Запуск

Двойной клик по **`start.bat`** — скрипт сам найдёт Node.js, поднимет сервер и откроет
браузер на свободном порту (обычно 3000). Остановить — **`stop.bat`** или `Ctrl+C`
в окне сервера.

Подробная инструкция со всеми частыми вопросами: **[ЗАПУСК.md](ЗАПУСК.md)**.

Если Node.js не прописан в системе, положите `node.exe` в папку `runtime` рядом с
`start.bat` — лаунчер подхватит его автоматически.

Альтернатива для разработки: `npm start`.

### Запуск через VS Code

В папке уже есть `.vscode/launch.json`, поэтому:

1. `Файл` → `Открыть папку…` → выбрать `PCBuilder-ERP`.
2. Открыть `server.js` (необязательно, но удобно).
3. Нажать **F5** (или `Запуск` → `Начать отладку`) и выбрать конфигурацию
   **«PCBuilder: запустить сервер»**.

Второй конфиг **«PCBuilder: проверка (smoke-тест)»** прогоняет весь сценарий
(заказ → оплата → сборка → отправка → получение) — запускать при работающем сервере.

## Адреса

Сервер печатает свой адрес при старте (порт по умолчанию — 3000, при занятости берётся следующий).
Пути внутри сайта:

| Что | Путь |
|---|---|
| Главная (выбор роли) | `/` |
| Кабинет клиента | `/client` |
| Панель сборщика | `/assembler` |
| Конфигуратор ПК | `/builder` |
| Отслеживание доставки | `/track` |
| Ссылка из SMS клиенту | `/track/<трек-номер>` |
| Состояние системы (JSON) | `/api/health` |

## Доступы

Паролей в репозитории нет: при первом запуске создаётся файл `secrets.local.json`
(в git не попадает) со случайными паролями, а сервер один раз печатает их в консоль.

| Роль | Логин |
|---|---|
| Сборщик / администратор | `admin` |
| Сборщик | `assembler` |
| Клиент | `+79990000000` |

Пароли берутся из `secrets.local.json` или из переменных окружения
`ADMIN_PASSWORD`, `ASSEMBLER_PASSWORD`, `CLIENT_PASSWORD`. Адрес сайта для ссылок
в SMS — `PUBLIC_URL` или поле `publicUrl` в том же файле.

## Интерфейс

Общая дизайн-система лежит в `public/style.css` — токены, тёмная и светлая темы,
компоненты (кнопки, поля, таблицы, карточки, канбан, drawer, модалки, тосты, ступени,
таймлайн, график), адаптив и режим `prefers-reduced-motion`.

- **Тёмная тема** включается автоматически по системной настройке, переключается в шапке,
  выбор сохраняется в `localStorage` и применяется до первой отрисовки (без мигания).
- **Ссылки на разделы** через хеш: `#/dash`, `#/orders`, `#/supplies`, `#/clients`,
  `#/stock`, `#/settings` в панели сборщика и `#/orders`, `#/profile` в кабинете клиента —
  работают кнопки «назад»/«вперёд» и можно отдать ссылку коллеге.
- **Горячие клавиши**: `Ctrl`/`⌘ + K` — фокус в поиск, `Esc` — закрыть окно, меню или drawer.
- **Состояния**: скелетоны при загрузке, пустые состояния с подсказкой, тосты на каждое действие,
  индикатор на кнопках во время запросов, а не «пустая страница при ошибке».
- **Адаптив**: от 360px до широких экранов; канбан скроллится по горизонтали, drawer
  превращается в шторку снизу, таблицы — в горизонтальный скролл.

### Конфигуратор (`/builder`) — сборка в один клик

Главная страница конфигуратора отвечает на вопрос «какой ПК мне нужен и сколько он стоит»,
не заставляя разбираться в сокетах и чипах памяти.

**Как это работает**

1. Клиент выбирает **сценарий**: офис и учёба, игровая, монтаж видео, 3D-моделирование,
   стрим и контент, универсальный.
2. Ставит **бюджет** ползунком (или кнопкой-пресетом).
3. Жмёт «⚡ Собрать за 1 клик» — алгоритм `lib/builder.js` перебирает каталог и возвращает
   готовую совместимую сборку: сокеты совпадают, тип памяти совпадает, блок питания перекрывает
   пиковое потребление, корпус вмещает видеокарту по длине, кулер рассчитан на процессор.
4. Клиент видит итог: цена, оценки по играм/монтажу/3D/офису/стриму, примерный FPS,
   запас блока питания, список деталей с **полными названиями** и два альтернативных варианта
   (дешевле / мощнее) — переключаются в один клик.
5. Кнопка «Взять эту сборку» → «Подкрутить детали вручную» — любую деталь можно заменить
   в каталоге, совместимость пересчитывается на лету.
6. «Оформить заказ» — доставка, оплата, получатель; заказ уходит в ERP как обычный.

**Сценарии с лендинга и из кабинета** ведут прямо в конфигуратор с подставленными параметрами:
`/builder?profile=3d&budget=250000` — сценарий и бюджет уже выставлены, сборка подобрана сразу.

**Ручной режим** (вкладка «Каталог»): 8 категорий, поиск, сортировка по цене и мощности,
переключатель «только совместимые» — несовместимые позиции подсвечиваются с причиной
(«Сокеты не совпадают: процессор AM4, плата LGA1700»).

- Итоговая цена считается сразу: комплектующие + сборка + доставка по тарифам из БД.
- Сборка сохраняется в `localStorage` — не теряется при перезагрузке.
- Собственная дизайн-система (`styles.css`): стеклянные поверхности, абстрактный фон
  с градиентными «орбами», акцентный цвет переключается вместе со сценарием.
- Тёмная и светлая темы проработаны одинаково, учитывают `prefers-reduced-motion`.

### Каталог комплектующих

`data.js` — единый источник правды, 155 позиций в 8 категориях (30 CPU, 24 GPU, 22 платы,
17 модулей ОЗУ, 16 БП, 16 кулеров, 16 корпусов, 14 накопителей):

- **Полные названия** в магазинном виде: `ASUS TUF GAMING B650M-PLUS WIFI`,
  `MSI GeForce RTX 4060 Ti Ventus 2X BLACK 16 ГБ` — без обрезок и троеточий, карточка
  показывает название целиком в любой ширине экрана.
- **Полные характеристики**: сокет, ядра/потоки, тип и объём памяти, частота, TDP, видеопамять,
  длина видеокарты, форм-фактор, список поддерживаемых сокетов у кулера, поддерживаемые
  платы и предельная длина видеокарты у корпуса, объём и интерфейс накопителя,
  мощность и сертификат БП, индекс производительности.
- При каждом старте `lib/catalog.js` сверяет `data.js` с таблицей `components`:
  новые позиции добавляются, существующие обновляются (цены, названия, характеристики),
  исчезнувшие архивируются или удаляются. Дубли и записи с пустыми характеристиками больше
  не накапливаются.

### Картинки комплектующих

В папке `images/` лежат девять изображений в едином стиле «тёмная студийная съёмка»:
`cpu.png`, `gpu.png`, `motherboard.png`, `ram.png`, `psu.png`, `storage.png`,
`cooler.png`, `pc_case.png` и баннер `welcome_bg.png` (оставлен от прежней версии конфигуратора).

- Каждая картинка — 1200×900 PNG: мягкий верхний свет, контактная тень, отражение
  на «полу» и контурная подсветка, которая отделяет деталь от фона карточки.
- Текстуры и подписи полностью свои, водяных знаков и чужих логотипов нет.
- Перерисовать весь набор можно одной командой:
  `python tools/make_component_images.py` (нужен Python + Pillow).
- Плитки категорий, карточки товаров, полоса «что уже выбрано» и корзина используют
  эти же файлы, поэтому новый комплект достаточно положить в `images/`.

## База данных

**SQLite** — файл `data/pcbuilder.db`. Схема создаётся автоматически при первом запуске,
демо-данные накатываются сами. Никакого MySQL и никаких внешних сервисов.

- Режим **WAL** + `busy_timeout` — чтение не блокирует запись, нет ошибок «database is locked».
- Таблицы: `clients`, `staff`, `sessions`, `components`, `orders`, `order_items`, `payments`,
  `shipments`, `shipment_events`, `supplies`, `supply_items`, `order_events`, `order_messages`,
  `settings`.
- `components` — каталог: полные характеристики в отдельных колонках (`brand`, `cores`,
  `memory_gb`, `form_factor`, `wattage`, `efficiency`, …) и длинные списки (сокеты кулера,
  поддерживаемые платы корпуса) в JSON-колонке `specs`. Флаг `archived` прячет позиции,
  которых больше нет в `data.js`, но на которые ссылаются заказы.
- `settings` — реквизиты компании и тарифы (сборка и доставка). Меняются в панели сборщика
  (`Настройки`) без правки кода; значения попадают в расчёт заказов и в печатные формы.
- **Миграции** в `lib/schema.js`: новые колонки в уже существующие таблицы добавляются
  `ALTER TABLE ADD COLUMN` при старте, идемпотентно — файл БД можно просто обновлять.
- Индексы на все выборки списков, дат и связей.
- Резервная копия: `Настройки → Скачать резервную копию` (консистентный `VACUUM INTO`
  в `data/backups`). Проверка целостности — `Настройки → Состояние БД` и `/api/health`.

## SMS-уведомления клиенту

Клиент получает сообщения на каждом этапе — без звонков и «а где мой компьютер?»:

| Этап | Что приходит |
|---|---|
| Оплата получена | сумма и «запускаем сборку» |
| Закупка комплектующих | детали заказаны у поставщиков |
| Сборка началась | мастер приступил к работе |
| Сборка готова | система собрана и протестирована |
| Отправлено | **трек-номер + ссылка на отслеживание** |
| Курьер везёт | адрес доставки |
| Прибыло в пункт выдачи | **«заберите до …», код получения** |
| Заказ получен | благодарность |

- **Канал выбирается в панели сборщика → раздел «SMS»**: журнал (без реальной отправки, тексты
  пишутся в `data/sms.log`), SMSC.ru (реальная отправка по api_id) или свой webhook.
  Переключение и тестовое сообщение — в том же разделе.
- **Тексты редактируются** там же: шаблон на каждое событие с подстановками
  `{order} {track} {link} {eta} {city} {address} {code} {total} {name} {company}`.
- **Журнал** `sms_messages` хранит каждое сообщение: что, куда, когда, статус и ошибку.
  Клиент видит те же сообщения в карточке заказа, мастер — в разделе SMS и в карточке заказа.
- **Клиент может отключить уведомления** в кабинете (Профиль → SMS-уведомления) —
  тогда сообщения не отправляются, но заказы и чат работают как раньше.
- Отправка никогда не ломает заказ: ошибка канала пишется в журнал со статусом `failed`,
  а сам заказ продолжает обрабатываться.
- Один и тот же этап не дублируется: «Сборка» и «Тестирование» дают одно сообщение.

API: `GET /api/sms` (журнал), `POST /api/sms/send`, `POST /api/sms/test` — только для сотрудника.

## Жизненный цикл заказа

1. **Клиент** собирает ПК в конфигураторе → «Оформить заказ» → заказ `Оформлен` (`new`).
2. Клиент **оплачивает**: карта / СБП / счёт / наличными при получении → статус `Оплачен`.
3. Сборщик видит заказ на канбане: `Закупка комплектующих` → поступление оформляется в разделе
   **Приёмка**; при полной приёмке заказ сам уходит в `Сборку`.
4. `Сборка` → `Тестирование` → `Готов к отправке`.
5. Раздел **Логистика**: оформление отправки (перевозчик, трек-номер, вес, ETA) → статус `Отправлен`.
   Клиенту доступен трек-номер и 4-значный код получения.
6. Клиент **подтверждает получение** кодом → `Доставлен`.
7. Сборщик закрывает заказ → `Завершён`.

Канбан-колонки перетаскиваются мышью: недопустимый переход подсвечивается красным и отклоняется
сервером. В карточке заказа вкладки: Состав · Оплата · Логистика · Переписка · История.

## Получение товара: как это работает

Подтверждение получения доступно **двумя способами** — оба закрывают заказ:

1. **В кабинете клиента** — кнопка «Подтвердить получение» на карточке заказа, ввод 4-значного кода.
2. **Публично, без входа** — на странице `/track/<трек-номер>`: вводите трек-номер, видите всю
   историю перемещения и подтверждаете получение тем же кодом из накладной. Ссылку сборщик
   копирует одной кнопкой в карточке заказа — можно отправить клиенту в SMS.

Код подтверждения **не** отдаётся в публичном API — иначе любой мог бы закрыть чужой заказ.
Если оплата была «при получении» — после подтверждения платёж закрывается автоматически.

## Разделы панели сборщика

- **Обзор** — выручка с графиком за 14 дней, заказы по статусам, загрузка сборщиков,
  лента последних событий (колокольчик в шапке), позиции, которые заканчиваются.
- **Заказы** — канбан по статусам (карточки с прогрессом приёмки, оплатой и сборщиком),
  фильтр «все / активные», поиск, «только мои заказы», новый заказ от имени клиента.
- **Приёмка** — поставки от поставщиков, привязка к заказу, приёмка на склад с автопополнением.
- **Клиенты** — база с поиском и сортировкой, карточка клиента: контакты, заметка, все заказы,
  быстрый заказ по телефону.
- **Склад** — остатки, резервы, пороги «заканчивается», фильтр по категориям, изменение
  остатков в один клик, добавление компонента в каталог.
- **Настройки** — реквизиты, тарифы, команда (добавление сотрудников для администратора),
  состояние БД и скачивание резервной копии.

## API (кратко)

```
GET  /api/meta                  справочники, тарифы, реквизиты (для всех)
GET  /api/health                состояние системы и целостность БД
GET  /api/settings              реквизиты и тарифы      PATCH /api/settings (сотрудник)
GET  /api/activity              лента событий (сотрудник)
POST /api/auth/register | /api/auth/login | /api/auth/logout   GET /api/auth/me
PATCH /api/me                   профиль клиента (+ смена пароля с проверкой текущего)
GET  /api/components            каталог    POST/PATCH /api/components (склад)
POST /api/orders (клиент)       GET /api/orders/my (клиент)  GET /api/orders (сборщик)
GET  /api/orders/:id            PATCH /api/orders/:id/status
GET/POST /api/orders/:id/messages
POST /api/orders/:id/pay | /payment/confirm | /ship | /tracking
POST /api/orders/:id/confirm-receipt | /receipt-confirm-by-staff | /assign | /cancel
POST /api/order-items/:id/receive
GET/POST /api/supplies          POST /api/supplies/:id/receive
GET/POST /api/clients           GET/PATCH /api/clients/:id
GET  /api/staff                 POST /api/staff (админ)   PATCH /api/staff/:id
GET  /api/stats                 сводка + график за 14 дней + загрузка сборщиков
GET  /api/admin/backup          резервная копия БД (сотрудник)
GET  /api/track/:number         публичный трекинг         POST /api/track/:number/confirm
```

Сервер отдаёт gzip для текстовых ответов, `ETag`/`304` для статики, заголовки безопасности
(`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`) и красивую страницу 404.

## Проверка

```
npm run smoke     серверный сквозной сценарий: заказ → оплата → сборка → доставка
npm run ui        рендер всех экранов конфигуратора + проверки каталога (без сервера)
```

`npm run smoke` прогоняет полный путь: заказ → оплата → закупка → сборка → тесты → отправка →
публичное отслеживание → подтверждение получения по коду → закрытие заказа.
Дополнительно проверяет арифметику заказа, целостность БД, запись настроек,
deep-link `/track/<трек>` и корректные MIME-типы ассетов интерфейсов.

`npm run ui` поднимает минимальный DOM, отдаёт каталог из `data.js` и проверяет:
рендер всех трёх экранов конфигуратора, отображение полных названий, отсутствие дублей
и пустых характеристик в каталоге, наличие картинок, а также корректность проверки
совместимости (конфликт сокета ловится, корректная сборка проходит).

API подбора: `GET|POST /api/quick-build?budget=150000&profile=gaming`,
сценарии — `GET /api/profiles`, каталог — `GET /api/catalog`.
